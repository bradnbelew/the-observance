# The Observance V5 resource pack

Status: current production source for Minecraft Java 1.21.11.

This is the only client-side installation required for the ARG. It carries the shared clerk-mark
font and the spatial audio used by the Deep Hold investigations. Every puzzle that uses either asset
also has a plain-text or visual fallback, so declining or losing the pack can reduce presentation but
cannot make the campaign unsolvable.

## Runtime contents

| Asset | Purpose |
| --- | --- |
| `assets/observance/textures/font/runes.png` | Clerk-mark atlas shared with Discord clue rendering |
| `assets/observance/font/runes.json` | `observance:runes` bitmap-font provider |
| `assets/observance/sounds.json` | Four ambient events, one generic testimony fallback, and six named Keeper events |
| `assets/observance/sounds/*.ogg` | Eleven authored mono Vorbis clips for distance-aware playback |

The atlas is generated from `discord/src/forge/runes.ts`; the web/Discord and in-world alphabets
therefore cannot silently diverge. Rebuild it after any glyph change with `npm.cmd run pack:build`
from `discord/`, then inspect the proof generated by `npm.cmd run pack:proof`.

The named testimony events are:

- `observance:keeper_voice.vaun`
- `observance:keeper_voice.mara`
- `observance:keeper_voice.sella`
- `observance:keeper_voice.orin`
- `observance:keeper_voice.brann`
- `observance:keeper_voice.iss`

`observance:keeper_voice` remains the accessibility/recovery fallback. The V5 plugin must select a
named event at the matching affidavit station and show the same clue in text. Missing sound, a
declined pack, or a reconnect must never consume the affidavit or block its completion flag.

## Minecraft text use

Rune text uses a normal JSON text component:

```json
{ "text": "VENT EAST BEFORE SECOND BELL", "font": "observance:runes" }
```

The marks are a practical civic notation in V5, not a supernatural master cipher. They teach one
small literacy rule and then support varied investigations; they are never the sole finale answer.

## Release procedure

1. Run `tools/package_assets.ps1` from the repository root.
2. Host `observance-resourcepack.zip` at a direct public HTTPS URL.
3. Run `tools/set_resource_pack_config.ps1 -Url <direct-https-url>` so the URL and SHA-1 in the
   plugin configuration are updated together.
4. Rebuild the plugin and copy the resulting V5 JAR plus config to the Paper server.
5. Join with a clean client, accept the pack, and verify every named Keeper event at its station.
6. On a disposable rehearsal clone only, temporarily set `resource-pack.required: false`, restart,
   decline the pack, and verify the textual fallback. Restore `required: true`, rebuild the plugin,
   and repeat the manifest/JAR checks before producing the release candidate. A production client
   cannot test this path because declining a required pack correctly disconnects it.

Before publishing the candidate, run `tools/audit_all.ps1`; the audit regenerates the glyph atlas,
packages deterministic bytes, reads the ZIP back, verifies the configured SHA-1, and rejects a stale
plugin/config pairing. Never copy an older ZIP forward merely because its URL still responds.

The pack format is pinned to `[75,0]`, the resource-pack format for Minecraft Java 1.21.11. Do not
change the server version without regenerating and testing both pack metadata and the Paper plugin.
