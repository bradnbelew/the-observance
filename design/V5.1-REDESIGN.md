# The Observance V5.1 — redesign source of truth

Status: **active redesign** (started 2026-07-15). This is the single decision record for the V5.1
pass. Where an older `design/` doc conflicts with this file, this file wins; conflicting docs are
pruned as each area is touched. Do not add new plan docs — record decisions here and build against them.

## Why

A zero-context critic review (four passes: puzzles, prose, web/onboarding, watcher/finale) plus
first-hand measurement found: strong story + fairness engineering + a WOW website, but a hollow
middle — a four-verb interaction monoculture (`slot 13` ×31, `handle` ×135, one rotation answer reused
3×), Hold rooms at ~5% content density, the entire ambient Watcher **switched off in production**, the
Unlit gutted into kiosks, zero required/asymmetric multiplayer, and an 8-second finale.

Director standards (binding): investigation woven with story (not walk-up mechanisms / naked ciphers);
no AI slop, no ARG-narrator mystery voice; environments match the fiction; no contradictions between
text and world; hard but fairly solvable and players always know where to submit; group play with
asymmetric moments; a finale that lands. Services (Supabase/Railway/Drive) are Codex's — any DB change
ships as a Codex prompt, never applied from here.

## Waves

1. **Reawaken the living world** — IN PROGRESS (see below).
2. **Rebuild the Unlit** — a blacked-out mirror of the spawn village that is a *main act*: real
   expeditions, scattered investigative puzzles, distinct per-house verbs, the stalking-figure/light
   tension, clear submission — not lore the group already knows.
3. **Diversify interactions + difficulty + submission clarity** — retire the slot-13/pull-handle
   default; convert naked ciphers to keyed/investigative (C07 model). Node-data edits = Codex prompts.
4. **Asymmetric multiplayer** — reuse the built per-player display-fragment primitive across nodes.
5. **Interior density + opening zip→region + prune doc swamp.**

  - `WorldDriftClock` stays OFF in V5 (it edits durable sculk).
  - `config.yml drama.enabled` flipped to `true` and cadence raised from ~1 beat/hour to a felt-but-
    restrained rate (window 5/30min, global 3min, per-player 20min); Attention gating keeps calm/grouped

- **Solve feedback.** Engine-path node solves (`V5MechanicsEngine.evaluate` COMMITTED) were fully
  silent; now the record acknowledges a filing with a soft chime + a plain actionbar "the record takes

## Wave 2 — rebuild the Unlit as a real mirror-world expedition

Done (2026-07-15). Preserved entirely: the mirror-village shell (well entry/exit, inventory escrow,
borrowed-lantern light budget, darkness exposure, the four-stage stalking figure that hunts the exposed
and rushes/extinguishes your placed light) — this was already excellent per the critic and needed zero
changes. The fix targeted only the seven house puzzles, which were "arrange pre-labeled items, pull
handle" with the answer printed on the evidence itself.

Zero changes to `design/ARG-V5-PHYSICAL-PREDICATES.json` — every mechanism (bookshelf mask, item-frame
rotations, tagged-item trays, answer sign, bounded route walk) is untouched, so **no Supabase hash sync
is needed for this wave**. All de-kiosking happened at the content/dressing layer:

- **Lamp (BI01)**: the wick-segment book used to state the dial answer outright ("clock stopped taking
  oil at bell seven"). Removed. Added a decorative, non-interactive stopped clock (an item frame fixed
  at the required rotation, tagged `STOPPED`, holding no predicate PDC) elsewhere in the house — the
  player finds it, reads it, and copies it onto the real dial. Brute-forcing the dial blind is gone;
  the answer comes from observation.
- **Coop (BI03)**: item lore used to print "before bell eight" / "marked: NONE" directly on the tooltip.
  Rewritten to purely observational text (peck marks, ripple wear, dust on the clasp) plus a caretaker's
  log giving the raw comparison (birds react within minutes; last confirmed activity vs. the bell-eight
  alarm from C03) so the conclusion is derived, not read. Added two disturbed-looking decoy items in a
  separate "field kit" crate near (never inside) the real tray, so filing requires genuine
  discrimination instead of "grab what's present."
- **Well (BI04)**: the three pressure maps had no authored content at all. Added bearing-note lore
  ("DUE" / "REVERSED" / "QUARTER-TURN") plus a legend lectern teaching the bearing→rotation mapping —
  players translate written bearings into frame rotations themselves.
- **Warm (BI06)**: item lore already gave raw comparable dates (good) but repeated the excavation-order
  date on every correct sample (redundant tell). Moved that reference date to a single posted order
  lectern and added two later-dated decoy samples, so "before Iss's cut" is a real date comparison
  across the whole tray, not a matched label.
- **Cairn (BI02) / Watch (BI05)**: already investigative on inspection (physical strata description;
  spot-the-forged document) — added a short procedural lectern to each reinforcing the reading method,
  no mechanism change.
- **Threshold (BI07)**: added a visible worn-path floor material along the exact safe route cells and a
  warning sign at the outer (wrong) lever, so the bounded walk is found by observation rather than blind
  repetition. Route/posture tolerances themselves were left untouched (avoids touching a working,
  fragile-adjacent spatial mechanic).
- Two hardcoded content-inventory manifests had to be updated to match the added dressing (legitimate
  syncs, not weakened audits): `V5EvidenceItemAppearanceAuthority.EXPECTED_ITEMS` (111→118) and its
  per-node `exactCounts` map (BI03 3→5, BI06 3→5, BI04 added at 3), mirrored in
  `tools/check_v5_content.py`'s `EXPECTED_EVIDENCE_APPEARANCE_IDS`. All self-tests and Python audits
  pass with the new counts.

New helpers added to `ObservanceCommand.java`: `placeDecorativeStoppedClock` (non-interactive fixed
item-frame prop) and `placeUnlitFieldKit`/`UnlitDecoy` (cosmetic decoy items rendered from the appearance
catalog, placed outside any managed predicate container so the installer's reconcile pass can never wipe
them). Both are pure world-dressing — no new predicate operations, no evaluator changes.

## Wave 3 — submission clarity, then interaction diversification

**Submission clarity: done.** Added a new Discord slash command, `/progress`, that reads the live
open-node docket (`investigation_nodes`, already carries an authored `input_surface` per node — this
data existed but was never surfaced to players) and states plainly, per open finding, which of the
three channels takes it: the world itself, this Discord record (`/answer`), or the Copperline site.
Read-only — no new tables/columns/RPCs, so **no Supabase migration is needed**, only a Railway redeploy
of the bot and the command registration that already runs on every boot. New files:
`discord/src/bot/commands/progress.ts`; new repo reads `getOpenInvestigationNodes`/`getCaseTitles`; new
voice entries `progressHeader`/`progressLine`/`progressNotLinked`. Typecheck and the three V5 Discord
self-tests (canon/binding/surface) pass.

**Interaction diversification / naked-cipher pass:** targeted, not exhaustive. A full redesign of all
82 nodes' interaction verbs is a multi-week undertaking on its own (see the critic's census: 35%
type-a-phrase / 33% item-in-slot / 23% rotate-frames) and was not attempted wholesale in this pass —
doing it carelessly at speed would risk exactly the "don't make mistakes" regression the director does
not want. What shipped: the Unlit's seven houses (Wave 2, the explicitly named priority) went from
answer-printed-on-the-item to genuinely derived. Remaining naked-cipher/monoculture nodes across
C01-C10 are catalogued in the critic report and are the natural next-session target; they were not
touched here to avoid partial, unverified edits to the hash-locked physical predicates authority under
time pressure.

## Known remaining blocker — KS01 fresh-install frame identity (pre-existing, not from this pass)

A full fresh old-world cutover build (`paper-v5-cutover-final2`, JAR SHA-256 confirmed against
`plugin/build/libs/observance-0.5.0.jar` at the time) reached **76/76 fixtures placed** and full route
traversal, then failed its final readiness audit:

```
IllegalStateException: V5 fresh physical install failed: KS01/strips: movable frame set is incomplete: 5/6 unique pieces present
  at ObservanceCommand.requireCleanPhysical / finishDeepHoldV5Build
  at V5PhysicalComponentInstaller.inspectReorderableFrameSets (line ~2296-2298)
```

Diagnosis so far (confirmed, not guessed):
- **Not a geometry/traversal bug** — unrelated to this session's Hold fixes (stair junctions, water
  containment, cistern anchor). The audit's own route/site counts are otherwise clean.
- **Not a frame-backing bug** — RCON-probed the actual world state at the six required offsets; the
  installer's self-heal (`reconcileItemFrame`, sets `POLISHED_DEEPSLATE` when backing isn't solid)
  correctly produced a solid backing at all six positions.
- **Not a content/data bug** — all six required evidence ids (`ks01_dzgvi`, `ks01_pvvkh`, `ks01_gsv`,
  `ks01_yzxp`, `ks01_lu`, `ks01_gsv_kztv`) exist exactly once each in
  `arc/v5/evidence-item-appearance.json`; `FRESH_FRAME_PERMUTATIONS.get("KS01:strips")` is a clean
  6-element permutation `[2,5,0,4,1,3]`.
- **Live coordinate lookup was unreliable mid-investigation** — the compacted fixture coordinate
  computed from `DeepHoldV4Plan.compactX/compactZ` did not match the coordinate actually written to
  the running server's `sites.yml` for `sella_pool`, and a follow-up RCON entity search at the
  `sites.yml` coordinate itself found zero item-frame entities within a generous radius. This may
  point at the real fault (an ordering/equality issue in `reorderableFrameSet`'s address matching, or
  a chunk-load timing race during fresh item-frame creation causing one of the six creations to
  silently fail) but was not chased to a confirmed root cause — the live world was left in a
  partially-applied, inconsistent state by the failed build (later fixtures showed unrelated standing-
  zone/gate findings too), which makes further RCON archaeology against that specific instance
  unreliable. **Not touched by this redesign pass** — pre-existing in `V5PhysicalComponentInstaller`'s
  `inspectReorderableFrameSets`/`freshFrameSource`/`frameItemIdentity` (lines ~2213-2300).

**Next step for whoever picks this up:** re-run the exact same fresh cutover from a clean
`paper-v5-playable` copy with a debug log added inside `inspectReorderableFrameSets`'s loop (which of
the 6 addresses has `exact == null` vs `identity == null`), or reproduce twice to check whether it's
deterministic (same address fails both times) or a timing race (different/no failure on retry). Until
this passes, the compact Hold cannot reach a "production-ready" fresh-install receipt, so the
production server must stay closed per the original launch-safety instruction.

## Wave 5 — the "doc swamp" was smaller than it looked

`tools/check_v5_freshness.py` already enforces a real current/archive boundary: every one of the ~150
`design/*.md` files not in its `CURRENT_DESIGN_DOCS` allowlist must open with a `SUPERSEDED ... ARCHIVE`
banner, and it does — verified by re-running the check. The volume was the actual problem (project
history genuinely is large), not incorrect or missing markers. **No files were deleted or moved** —
deleting deliberately-preserved, correctly-quarantined history was the wrong fix for a
discoverability problem, and this file plus `design/V5-SUPERSESSION-MAP.md` (updated to list this file
first) are the fix: one place a reader lands that says what's current. `V5.1-REDESIGN.md` was added to
both the freshness checker's allowlist and the supersession map's authority table so this file is
itself recognized as current, not flagged as drift.
