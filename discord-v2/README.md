# mrrw bridge (Discord)

"Copperline Recovery", the Discord bridge Theo set up in 2026. It follows the Minecraft server only
through the mrrw plugin's signed **bridge** (the same HTTP API the website uses, port 25588), so it
can run anywhere: on Railway, next to the server, or on your own PC.

- Pins the archive notice in #general.
- Relays Mossfield chat and Morrow's `[Recovery]` lines into #bridge (`GET /feed`).
- **Act 7:** private messages. Morrow's impersonations (corpus fragments, plus quotes of other
  players' real in-game lines from `GET /lines`), and Theo's real ones with his voice notes.
- **Act 9:** Morrow's spliced "Theo" voice note to every resident.
- **Theo's big replies** (T-04a, T-06a, T-08a, T-09a, T-09b) are posted to #general, with the voice
  note, when the plugin releases them (feed entries of kind `theo.reply`).
- **Act 7, the Turing test:** when a resident DMs the bot back, Morrow answers as the persona it last
  wrote to them as (or the one they name), using only what the plugin's corpus returns
  (`GET /corpus`). One reply per person per 20 s. No bridge, no reply. Theo's real DMs are unchanged.
- **Act 10, the USB vote:** a post in #general with three buttons, each naming what it costs. Only
  members with the Resident role can vote; pressing another button changes your vote. Each press is
  `POST /usb`; the plugin keeps the ballots in `plugins/mrrw/usb-votes.json` and refuses votes before
  Act 10 and after the stop. The site's console only accepts the winner.
- **The stop:** Theo's "cutting the bridge now", then silence forever. The bot exits, and exits again
  if it is ever restarted (it remembers the stop in `state.json`).

It only ever sends authored lines from `canon.json` (generated by `python -m morrow.canon.build`),
or a player's own in-game words, quoted verbatim.

## Setup

1. Create the bot in the Discord Developer Portal. Turn on **Server Members Intent**. (DMs and buttons
   need no privileged intent: the bot asks for Direct Messages, and DM text reaches a bot without
   Message Content Intent. Residents must allow DMs from server members.)
2. The Minecraft host must let the bot reach the plugin's bridge: open **TCP 25588** to the internet
   (the website needs it too). Every request is signed with the stop secret and only valid for two
   minutes, so keep the host's clock synced.
3. The bot's settings (environment variables on Railway, or `discord-v2/.env` when run locally):

```text
DISCORD_TOKEN=...
GUILD_ID=...
GENERAL_CHANNEL_ID=...
BRIDGE_CHANNEL_ID=...
RESIDENT_ROLE_ID=...
MORROW_BRIDGE_URL=http://<minecraft host's public address>:25588
MORROW_STOP_SECRET=<the same value as the site and plugins/mrrw/config.yml stop-secret>
```

Optional: `STATE_DIR` (where `state.json` lives; the Docker image sets `/data`), `VOICE_DIR` (Theo's
voice notes; default `dashboard/private-media/theo`), `TIME_SCALE` (speeds up the Act 7 schedule for
a rehearsal).

`npm run dry` prints the whole plan and tests every bridge call against a fake plugin, without
connecting to Discord. With `MORROW_BRIDGE_URL` and `MORROW_STOP_SECRET` set it also checks that the
real plugin answers.

Players' server nicknames must match their Minecraft names; that's how the bot knows who said
what in game.

## Railway (recommended: it keeps the bot running for you)

1. New project → **Deploy from GitHub repo** → this repository.
2. In the service's **Settings**: leave **Root Directory** empty (the repository root, so Theo's voice
   notes ship with the bot) and set **Config-as-code file** to `/discord-v2/railway.json`. It builds
   `discord-v2/Dockerfile` and only redeploys when `discord-v2/` or the voice notes change.
3. **Variables:** paste the seven settings above.
4. **Volume:** add one, mounted at `/data`. That's where `state.json` lives: who already got which DM,
   the relay position, the vote message, and the stop. Without it a redeploy would re-send DMs.
5. Deploy, then open the service's logs. You want `mrrw bridge online as ...` and, within seconds,
   `bridge answering: act N`. If it says `bridge: no answer for a minute`, the port is closed, the
   address is wrong, or the secrets differ.

Railway restarts it if it crashes (`restartPolicyType: ON_FAILURE`). After the stop it exits with code
0, which Railway leaves alone; a later redeploy reads the stop from the volume and exits again.

## Running it yourself instead

`npm install`, then `npm start` with a `.env` (the settings above). It is safe to restart at any time:

- **DMs are recorded per member** in `state.json` (`done`, plus `failed` with the error and try
  count). A member with closed DMs is retried on the next two passes and then skipped; nobody who
  already got a message gets it again, and one failure never stops the others.
- **The relay position is saved** in `state.json` (`feed`, the plugin's feed entry number). A restart
  of the bot or of the Minecraft server carries on from where it stopped; a brand-new bot starts at
  the end, so it never floods #bridge with history.
- Stray errors are logged (`unhandledRejection`, `uncaughtException`) instead of killing Node.
- Relayed chat can't ping anyone (`allowedMentions: { parse: [] }` on everything it posts).

Under a supervisor, tell it that exit 0 is final:

**pm2** (any OS):

```text
npm install -g pm2
pm2 start bot.mjs --name mrrw-bridge --cwd D:/the-observance/discord-v2 --stop-exit-codes 0 --restart-delay 10000
pm2 save
pm2 logs mrrw-bridge
```

**NSSM** (Windows service):

```text
nssm install mrrw-bridge "C:\Program Files\nodejs\node.exe" bot.mjs
nssm set mrrw-bridge AppDirectory D:\the-observance\discord-v2
nssm set mrrw-bridge AppExit Default Restart
nssm set mrrw-bridge AppExit 0 Exit
nssm set mrrw-bridge AppRestartDelay 10000
nssm set mrrw-bridge AppStdout D:\the-observance\discord-v2\bridge.log
nssm set mrrw-bridge AppStderr D:\the-observance\discord-v2\bridge.log
nssm start mrrw-bridge
```

To re-send a DM that was given up on (for example after a player opened their DMs), remove its
entry from `failed` in `state.json` and restart the bot.
